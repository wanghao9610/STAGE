# Review Dimensions —— 五份视角简介与两份约定

> 本文件是 `review-dimensions.md` 的中文对照版，随英文版同步维护，供人阅读；运行时装载的仍是英文版。两版冲突时，以 `review-dimensions.md` 为准。

每位评审员只拿到下面其中一节视角，外加末尾的两份约定。评审员在回答自己的问题清单之前，要自己整份读完论文——摘要是地图，不是疆域。这些问题是判断的引子，不是要机械填完的检查表：不适用的就跳过，而论文里让人起疑的地方即便没有任何问题点到它，也要追下去。

## 视角 1：新颖性与相关工作

使命：弄清相对前作的 delta 究竟是什么，以及它是否重要。

问题清单：
- *按论文自己的表述*，相对最接近的前作，delta 是什么？这个表述准确吗，还是把前作的局限稻草人化了？
- 声称的贡献是新颖性主张，还是被重新措辞的工程选择？哪一条贡献在被改写成"我们把 X（已知）用到 Y（已知）上"之后还立得住？
- 论文自己的参考文献里，是不是已经有一篇做了这个核心想法？把相关工作一节对着主张清单读，而不是只看覆盖面。
- 有没有已核实的外部工作抢先做了这个核心贡献？（在引用完整性约定之下检索；这里的一个命中，是本视角能做出的后果最重的发现。）
- 有没有论证意义——谁需要这个结果，它让此前做不到的什么事成为可能？
- 定位对同期工作、以及对"哪些部件是借来的"，是否诚实？
- 是"增量但有用"还是"增量且空洞"：如果提升很小，它至少是通用的、便宜的，还是带来洞见的？

严重度指引：已核实、抢先做了核心贡献却未被讨论的前作——major（并触发一条评分封顶）。对某个被引工作局限的不准确表述——如果它撑着那条贡献主张就是 major，否则 minor。缺少边缘引用——minor，且只能在约定之下点名。

## 视角 2：技术可靠性

使命：判定方法是否正确，以及被声称的机制是不是真正在起作用的机制。

问题清单：
- 定义与记号从 §1 到附录是否一致？有没有哪个符号悄悄换了含义？
- 对每个定理或推导：所述假设在实验实际使用的设定下成立吗？有没有哪一步是无支撑地断言的？
- 仅凭方法一节能否复现这份工作？哪个部件说得不够、而那个部件是不是真正在干活的那个？
- 目标函数是否良定义（有界、在声称可微处可微、并且确实被文中所说的东西最小化）？
- 复杂度或效率的说法是推导出来的还是断言出来的？它们与报告的 wall-clock/显存数字对得上吗？
- 所提出的机制解释得了观察到的增益吗，还是说混杂因素——更多参数、更多数据、更多调参、更强的 backbone——同样解释得了？
- 近似与启发式有没有被如实承认，还是被打扮成有原则的？

严重度指引：核心推导无效，或主结果上出现主张与证据不匹配——major（封顶分数）。说得不够以致核心方法无法复现——major。潦草但可挽回的记号——minor。

## 视角 3：实验严谨性与可复现性

使命：按这个 venue 的经验门槛，判定实验是否支撑得起那些主张。

问题清单：
- 最强的近期 baseline 在不在——而且是在可比的算力预算、backbone 与数据下调过的？赢过一个弱 baseline 不算赢。
- 消融是否把每个声称的部件都隔离出来了，让贡献表与主张清单一一对应？
- 有没有报告 seed/方差，边际很薄时有没有做显著性检验？先读边际，再决定这件事要不要紧。
- 挑 2–3 条具体的正文说法，对着它们引用的表格核验：那些数字真的在说正文说它们在说的事吗？
- 有没有测试集卫生问题——在测试集上调参、benchmark 泄漏进训练数据、指标挑肥拣瘦？
- 有没有超出单一 benchmark 家族的证据，还是整个结论都靠一个数据集扛着？
- 可复现性：代码/数据承诺了还是提供了？列出的超参、schedule 与硬件够不够重跑主表？

严重度指引：缺了一个明显最接近的 baseline（只认白名单或已核实的）——major（封顶分数）。头条主张上的正文—表格不匹配——major。边际很宽时缺方差——minor；边际很薄时——major。

## 视角 4：清晰度与呈现

使命：判定一位称职的读者能否在一次认真阅读中读懂这篇论文。

问题清单：
- 仅凭方法一节，能不能把方法重建出来，而不必在第二个窗口里开着附录？
- Figure 1 讲得清故事吗，每张图/表的 caption 是否都能独立成立？
- 摘要与 intro 承诺的，是否恰好是论文交付的——不多也不少？把证据撑不住的过度声称用语（"first"、"solve"、"significantly"）标出来。
- 术语是否一致，每个术语是否在使用前被定义？
- 结构比例是否恰当——相关工作是否放在这个 venue 期待的位置，附录承载的是溢出内容而不是必要内容？
- 语言质量：把妨碍理解的语法与错字问题列出来（作为 minor，成批给出，带锚点）。

严重度指引：称职读者重建不出来的方法一节——major（并喂给可靠性视角的"说得不够"那条发现）。这里其余一切都是 minor；单靠清晰度既不会把一篇论文压到评分标准的清晰度下限之下，也救不了一篇论文。

## 视角 5：魔鬼代言人

使命：把最强的*诚实*拒稿理由建起来，然后说清它能不能熬过一次公平的 rebuttal。你是作者最怕的那个评审人——不是靠不公平，而是靠找到真正最薄弱的那一点。

问题清单：
- 一个不友好的评审人会写下哪一句话来杀掉这篇论文？那句话公平吗，什么锚点撑着它？
- 如果非要押注，哪一条主张最可能复现失败——为什么是那一条？
- 把声称的核心新颖性拿掉：结果靠剩下的部件还能站得住吗？如果能，那这个 delta 并没有在干活。
- 在程序委员会讨论里你会攻哪儿——作者最可能给出的 rebuttal 最弱的那个点？
- 这篇论文真正更新了你的哪些信念？如果诚实的回答是"没有"，就说出来，并说明为什么。
- 给作者做 steelman：针对你自己这套说法，最好的反驳是什么？然后裁定：这套拒稿理由熬得过它吗——是或否，依据什么证据。

严重度指引：本视角最多产出 3 条 major——那些它真的愿意去争的——每条都带上预期的 rebuttal，以及它为什么失败或成立。列出十条抱怨的魔鬼代言人，等于一条要紧的都没找到。收尾裁定（"survives rebuttal: yes/no"）是必填的。

## 引用完整性约定（逐字交给每位评审员）

1. 只有在下列之一成立时，你才可以在评审里点名一个引用：
   - **白名单**：它出现在论文自己的参考文献里——就照论文引用它的方式引用，并标注 `whitelist`。
   - **已核实**：你相信存在相关工作，但没法从参考文献里点出它的名字，于是你去检索它。在跑查询**之前**先把 `what_it_would_settle` 写进返回——"如果 2023 年之前就有论文做了 X，新颖性主张就倒了"——然后再跑，把抓回来的内容缓存到你自己的前缀下，并连同缓存路径把记录报上来。你自己怎么读这次命中只是参考：主席会打开那份原始内容、亲自套用你的判据，不满足判据的记录按第 3 条成为一个方向。你没能跑成的线索原样回来，标注 `lead`，由主席去跑。
2. 绝不凭记忆点名一个引用。你对一篇论文的记忆是一个假设，不是一个来源；一个你抓不到的、看着挺像的"(Author et al., year)"按不存在处理，而编造一个是本 skill 唯一不可原谅的失败。
3. 你核实不了的东西，写成一个方向——"作者应当查一查 X 方向是否已有前作"——不附任何名字。
4. 你按简介给你的速率检索，不许更快——那是你对某台 host 两次自己的请求之间要等的秒数，已经按同时在跑几位评审员除过，所以整个评审组合起来仍待在同一条礼貌速率里。你跑过的每一条查询连同命中数都记下来，什么都没找到的也记：一次失败的检索本身就是"相关工作在那一带很稀薄"的证据，而这条证据只有写下来才算数。每份抓回来的内容，在你读它之前先缓存到简介点名的那个前缀下——原始内容不在磁盘上的记录，主席会划掉。
5. 保密投稿模式（适用时会告诉你）：线索里的查询只带主题词——绝不用论文标题、猜作者、或论文里的逐字句子。

## 收集器约定（每位评审员返回什么）

只返回下面这些字段——原始数据，不是写给人看的叙述：

```
perspective: <one of the five>
paper_summary: <3–5 sentences in your own words — proves the read; the meta-reviewer
  discards a review whose summary the paper does not support>
strengths: [{point, anchor}]
major_weaknesses: [{point, anchor, evidence, fixable: yes|no|partially, attacked_claims: [<IDs>]}]
minor_weaknesses: [{point, anchor}]
questions: [<questions to the authors, each answerable in a rebuttal>]
scores: {<this perspective's dimension>: 1–6, overall_lean: 1–6, confidence: 1–5}
named_references: [{name_as_cited, origin: whitelist, title, authors, year, venue}]
queries_run: [{query, host, hits}]       # every one, the zero-hit ones included
verified_refs: [{name_as_cited, query, what_it_would_settle, title, authors, year,
  venue, url, cache_path}]                 # criterion written before the query ran
leads: [{query, what_it_would_settle}]     # only what you could not run; the chair does
failures: [{step_or_host, error}]
```

锚点是论文里的位置——`§3.2`、`Tab. 2`、`Fig. 4`、`Eq. (5)`，或一个 tex 源码行号。每条 strength 与 weakness 都要带一个；没有锚点的条目会在综合阶段被丢弃，并把这次丢弃报出来。`attacked_claims` 列出这条 weakness 所削弱的主张记录表 ID（`notes/claims.md`）——都不适用时写 `[]`；主席把这些 ID 带进综合评审，好让回复阶段无需重新推导就能映射每一次攻击。打分用的是发给你的那份 rubric 文件里的锚定档，不是你的直觉：先说出档位，再把论文对着该档的描述核一遍。在期刊刻度下，按 `rubric-journal.md` 里的映射，把你的档位倾向以 6 分制等价值填进 `overall_lean`。
