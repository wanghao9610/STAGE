STAGE

Every STAR needs a STAGE

STAR 的学术写作伴侣 —— 把一个研究项目变成一篇正式投稿的论文， 全程不丢失监管链：手稿中的每个数字都能追溯到带指纹的证据文件，或显著标记为缺失； 每个论断都在同一份台账中从提出追踪到核实。

为何选择 STAGE

每个数字都有出处。
每个论断都有案可查。

当数字散落在聊天记录里、论断只存在于某个人脑中时，论文就会腐烂。 STAGE 把整条监管链 —— 证据、论断、评审、投稿 —— 全部搬进仓库。

一致的手稿布局

章节、带源文件的图、表格、参考文献、会议样式，在 manus/ 下各有唯一、可预期的位置 —— 且开箱即可编译。

只读的证据层

STAR 产物或手工登记的证据被快照进 mates/，每个文件的指纹记录在 MANIFEST.md。证据单向流动 —— 绝不在原地修改。

论断台账作为中枢

notes/claims.md 把每个论断的表述 ⇄ 证据 ⇄ 状态连接起来 —— proposed → drafted → verified —— 从故事种子一直到投稿。

杜绝编造的边界

manus/ 中的每个数字，要么追溯到带指纹的 mates/ 条目，要么写成 \todo{...} —— 没有第三种状态。关于被引论文的断言必须能对上阅读笔记；会议规则只以用户确认的事实录入。可见的 \todo 是一种状态；一个貌似合理却编造出来的数字则是缺陷。

确定性检查归脚本，判断归技能

bash execs/run.sh 用 latexmk 在树外构建；lint.sh 机械地拦截未定义引用、\todo 标记、页数超限与匿名性泄漏。一切需要判断的工作交给十六个技能。

投稿周期即数据

每次投稿都活在 cycls/<venue>_<year>/ 中：用户确认的 venue.yml、收到与模拟的评审、回复信，以及冻结的投稿记录 —— 包括拒稿在内，因此下一次尝试从上一次结束的地方开始。

AI 代理原生，与 STAR 配对

同一套十六个技能同时发布给 Claude Code、Codex、Cursor 与 Kimi Code —— 中英双语。可与 STAR 仓库配对、一条命令导入证据，也可独立使用、手工登记证据；下游一切完全相同。

项目结构

八个目录。
一条监管链。

缩写命名沿用 STAR 的约定：输入简短、搜索无歧义， 并且在每一篇基于 STAGE 写作的论文中保持一致。

tree ~/my-paper
STAGE/ ├── manus/ # 手稿本体 │ ├── main.tex # 入口 —— 始终按预印本编译 │ ├── secs/ # 章节：<n>_<slug>.tex │ ├── figs/ # 渲染好的 PDF；figs/srcs/ 存放源文件 │ ├── tabs/ # 表格，由证据生成 │ ├── bibs/ # reference.bib │ └── stys/ # arxiv.cls（外观）+ stage.sty（宏） ├── mates/ # 导入的证据 —— 只读 │ └── MANIFEST.md # 指纹台账 ├── notes/ # 故事、论断、大纲、符号约定 │ └── refs/ # 每篇论文的阅读笔记 ├── cycls/ # 投稿周期：<venue>_<year>/ ├── tasks/ # 修改草稿与承诺清单 ├── wkdrs/ # 构建与报告（gitignored） ├── execs/ │ ├── run.sh # ← 唯一的构建入口 │ ├── update.sh # 同步技能；--adopt 安装骨架 │ └── scpts/ # import.sh · lint.sh ├── .env # 本机配置（绝不提交） └── AGENTS.md # 人与代理共用的指令
manus/Manuscripts —— 论文的 LaTeX 源文件
mates/Materials —— 带指纹的证据快照，只读
notes/写作元数据 —— 故事、大纲与论断台账
cycls/Cycles —— 每次投稿尝试一个目录
tasks/Tasks —— 修改草稿与承诺勾选框
wkdrs/Work directories —— 构建与临时报告，绝不提交
scpts/Scripts —— 证据导入与确定性检查

写作工作流

十六个技能。
一条监管链。

从导入证据到冻结投稿 —— 每个技能都把自己的状态写入项目文件， 因此整篇论文在任何时候都可审计、可续作。

✦

搭建接好仓库，导入带指纹的证据。

/stage-proj-adopt †

把新建或已有的论文仓库接入 STAGE —— 草稿里已有的数字成为 unsourced 论断，而非沉默的债务。

/stage-evid-curator

运行导入、登记手工投放的文件、规范化杂乱的导出，并提出论断⇄证据映射。

✦

规划打磨故事，搭起论文骨架。

/stage-stry-coach †

对话式的故事打磨：卖点、带论断 ID 的贡献、投稿理由 —— 同时播种论断台账。

/stage-outl-planner †

故事 → 骨架：章节页数预算、图表计划、论断→章节分配。

/stage-refs-curator

参考文献治理、带可引用事实的阅读笔记、去找没人点过名的工作、相关工作的定位。

✦

写作从证据起草，绝不凭记忆。

/stage-sect-drafter

每次运行起草一节，依据该节简报、映射好的证据与论断 —— 缺失的数字写成 \todo{}。

/stage-tabs-builder

表格只从 mates/ 证据生成 —— 每个数据行一条 % src: 指纹注释。

/stage-figs-designer

端到端负责每张图：用途、figs/srcs/ 下的可编辑源文件、渲染出的 PDF。

✦

打磨与审计追溯每个数字，核对每条引用。

/stage-copy-editor

清晰度、行文与符号一致性 —— 技术含义与任何数字都不可触碰。

/stage-clms-auditor

提取手稿中的每个数字并逐一追溯指纹：matched / mismatched / unsourced。

/stage-cite-auditor

每个 \cite 都能解析；每条关于被引工作的断言都能对上阅读笔记。

✦

投稿周期评审、回复、冻结。

/stage-peer-reviewer

五视角的模拟程序委员会，在引用诚信契约下评审。

/stage-resp-writer †

评审 → 要点台账 → 篇幅符合会议限制的回复信，每个承诺的修改都是一个勾选框。

/stage-subm-packer †

预检、用官方模板套件转换版式、打包、投稿记录、冻结标签。

✦

纵览报告全局进度，指出下一步。

/stage-flow-status

只读的全局地图 —— 大纲、台账、清单、投稿周期状态 —— 并给出唯一的下一步动作及其确切命令。从不写入。

† 标记五个只能显式调用的技能：它们只在你点名时运行，因为决策点 —— 接入、故事、大纲、回复、投稿 —— 始终由你把持。

快速上手

五步得到一篇可编译的论文。

从模板全新开始 —— 或者在已有的论文仓库里运行 update.sh --adopt， STAGE 会围绕你的草稿安装骨架，不移动任何文件。

zsh — my-paper
# 1 · 从 STAGE 模板建立论文仓库 —— 一篇论文，一个仓库 ❯ git clone https://github.com/wanghao9610/STAGE my-paper && cd my-paper ❯ rm -rf .git && git init # 去掉 STAGE 的历史 # 2 · 配置本机运行环境 ❯ cp .env.example .env && $EDITOR .env # STAR_HOME（可选）· LATEX_ENGINE · ANON # 3 · 从配对的 STAR 仓库导入证据 —— 或把文件放进 mates/manual/ ❯ bash execs/scpts/import.sh # 4 · 构建与检查 —— 全新克隆开箱即可编译 ❯ bash execs/run.sh ❯ bash execs/scpts/lint.sh # 5 · 进入工作流 —— 它会告诉你唯一的下一步动作 ❯ /stage-flow-status ❯
