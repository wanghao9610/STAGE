# STAGE 中自然可信的学术表达

**语言：** [English](human-writing-guide.md) | 简体中文

STAGE 面向一篇研究论文，并要求每项论断都能从稿件句子追溯到证据。
在这套工作流中，自然写作不是研究内容完成后的表面润色，而是让审稿人容易理解这条可追溯论证链，同时不增加仓库没有支持的重要性、确定性、细节或个性。

本指南约束 `stage-sect-drafter`、`stage-copy-editor` 以及 `stage-peer-reviewer` 的清晰度审阅。
[写作工作流规范](writing-workflow-conventions.zh-CN.md)中的事实防线、引用、归属和文件所有权规则始终具有最高优先级。

## 1. 判断文风前先读取论文记录

STAGE 中的自然度受项目记录约束，不由一段通用风格提示决定。
草拟或修改一段文字前，应读取控制该段内容的记录：

| 记录 | 它对正文的约束 |
|---|---|
| `notes/story.md` | 论文的主线、问题、核心思路和贡献；可以把表达写得更清楚，不能扩大这些内容 |
| `notes/claims.md` | 论断原文、类型、陈述位置、证据和当前强度；这是改写的语义边界 |
| `mates/MANIFEST.md` 和映射的 `mates/` 文件 | 结果是否有指纹、证据实际包含什么 |
| `notes/refs/<ABBREV>.md` | 可以怎样描述被引工作；支撑句子的是 `## Citable facts`，而不只是参考文献条目 |
| `notes/outline.md` | 每个 `manus/secs/<n>_<slug>.tex` 文件的任务和页数预算 |
| `notes/notation.md` | 规范术语、符号、缩写及首次出现位置 |
| `notes/style.md`（若存在） | 作者确认的声音和节奏偏好；它只提供偏好，不提供事实或论断 |
| `cycls/<cycle>/venue.yml` 和 `.env` 中的 `ANON` | 已确认的篇幅和匿名约束 |

这些记录若彼此冲突，不能在正文中悄悄调和。
应把冲突报告给拥有相应记录的工作流。

## 2. 改写后仍须保留完整追溯链

STAGE 有两个不同的处理单位：**段落是组织论证的单位，句子是机械审计的单位**。
为了改善推理可以重组段落，但改写后的每个句子仍须保留它在追溯链中的位置。

### 实验结果和其他外部数字

正文中的数字必须继续连接到论断台账行、该行的证据链接，以及有指纹的 `mates/` 条目。
一条 `% src:` 注释只覆盖它所引领的一个句子。
不能让有来源的句子脱离对应注释，不能合并分别受不同来源控制的句子；拆句后也必须重新判断每个结果由哪个来源覆盖。

如果编辑暴露出无来源数字，应保留或加入 `\todo{...}`，并通过拥有该记录的工作流显式登记台账债务。
不能为了写得具体而填入记忆中的数值。

### 对被引工作的陈述

相关工作句子的强度和范围不得超出对应阅读笔记。
组合引用不是装饰：一句话把同一属性归给三篇论文时，三篇论文的笔记都必须支持这一属性。
即使读起来更顺，把“使用”改成“依赖”，或把“评估”改成“证明”，仍然是在改变论断。

### 论断强度与贡献归属

必须尊重 `notes/claims.md` 中的 `proposed`、`drafted`、`verified`、`unsourced`、`weakened` 和 `dropped` 状态。
不能把相关性写成因果，把特定评估条件下的结果写成普遍结论，也不能把组件贡献扩大成整篇论文的贡献。
行为主体同样重要：本论文证实的内容、证据来源报告的内容、既有工作主张的内容和作者的解释必须彼此分开。

### 受保护的稿件结构

引用键、标签、交叉引用、公式、LaTeX 命令、`\todo{}`、`% src:` 注释、规范术语和投稿格式要求均视为受保护内容。
正文保持一行一句，使来源注释与它控制的句子维持稳定的两行结构。
修改标点或句子边界后，必须重新检查这些结构关系。

## 3. 按论文组成部分的实际任务写作

当一段文字只是在执行泛化的“学术写作功能”，而没有完成 STAGE 分配给它的任务时，最容易出现公式化表达。
应通过项目结构恢复这段文字的具体职责。

| 位置 | STAGE 检查对象 | 改写方向 |
|---|---|---|
| 摘要 | `notes/story.md` 中的主线和贡献 claim ID；台账中的已验证范围 | 直接交代问题、方法区别、有支撑的结果和有边界的贡献，不作仪式化铺垫 |
| 引言 | 小节 brief 和贡献台账行 | 说明具体缺口以及核心思路为何能够处理它，不使用无支撑的“范式转变”叙事 |
| 相关工作 | 阅读笔记和术语规范 | 建立“命题—来源—与本文差异”的关系，不写“已有研究表明”式匿名叙述 |
| 方法 | 术语表、论断类型和小节 brief | 说明主体、操作、输入、输出和设计理由；当主体不影响理解时，被动语态完全可以保留 |
| 实验 | 有指纹的证据和结果论断 | 先给足解释结果所需的设置，再写结果，最后只写证据能够支撑的推论 |
| 图表标题 | outline 中的图表目的及来源映射 | 说明展示内容、阅读方式和有支撑的要点，不把 caption 写成第二份摘要 |
| 局限性 | 评估范围以及 `weakened` 或 `unsourced` 论断 | 写明准确边界、它造成的后果，以及什么证据能够解决问题 |
| 结论 | 主线、已验证论断和未解决边界 | 回答本论文的问题，不用“该领域将继续蓬勃发展”式泛化展望收尾 |

页数压力不能成为损失含义的理由。
向当前投稿周期已确认的页数预算压缩时，应先删除重复背景、重复解释和空洞路标，再考虑限定语、证据或技术区别。

## 4. 诊断论证故障，而不是禁用词语

`lint.sh` 使用类别名把可能需要检查的位置交给作者。
这些类别描述 STAGE 论证中可能出现的故障，不是禁词表，也不判断文本作者身份。

- `inflated-significance`：文字宣称的重要性超出已映射贡献或已验证后果。
- `vague-attribution`：需要来源的陈述没有明确对应论文、证据生产者或作者立场。
- `shallow-analysis`：结果后接“从而彰显”“进而说明”或类似尾句，却跳过真正的推理步骤。
- `formulaic-contrast`：“不仅……而且……”“不是……而是……”或整齐三段式制造了方法或论断台账并不需要的对立。
- `stock-signposting`：文字重复宣布标题和段落顺序已经表达清楚的内容。
- `generic-outlook`：局限性或结论以乐观表态收尾，却没有指出未解决论断、缺失证据或具体研究问题。
- `manufactured-depth`：口号、戏剧化短句或“真正的问题在于”制造了证据并未赢得的强调。
- `stock-diction`：多个装饰性抽象词堆叠在一起，替代了更精确的规范术语。
- `chatbot-residue`：问候、表扬、道歉、知识截止声明或继续服务邀请混入稿件。

单独出现 *however*、破折号、被动语态、三项列举、长句或正式术语不构成问题。
凡是承担必要比较、标明真实推论、保持领域惯用表达或符合作者确认样本的结构都应保留。
除明显的聊天机器人残留外，只有多个信号共同出现，或同一模板跨小节重复时，才值得提出公式化表达问题。

## 5. 使用作者风格档案，但不制造人格

`notes/style.md` 是可选文件，只有 `stage-copy-editor style` 可以写入。
文件存在时，从其中的样本恢复可观察偏好：句长与节奏、语态、段落开头、过渡方式、限定强度、列举、时态、公式密度、标点以及本论文避免的结构。

优先级固定为：

1. 证据和引用边界；
2. 论断台账；
3. `notes/notation.md` 和投稿格式规则；
4. 风格档案。

样本提供的是设置，不是可以复用的句子。
不能从一个段落推断整篇论文的人格，不能借用被引作者的声音，也不能为了显得不像机器而加入幽默、情绪、自传信息、故意错误或第一人称感想。
没有风格档案时采用克制的学术默认值：具体论断优先，术语稳定，在主体影响解释时明确主体，句长随推理需要变化。

风格档案只约束 `manus/` 下的正文。
它不改写工作流记录，也不覆盖投稿场所规定的审稿回复语体。

## 6. 通过受保护内容对照完成改写

草拟或润色一个小节时：

1. 通过 `notes/outline.md` 解析小节，并用分配给它的论断说明每个段落的任务。
2. 冻结字面不变量：数字、公式、键、标签、交叉引用、`% src:`、`\todo{}` 和规范术语。
3. 冻结语义不变量：论断强度、适用范围、归属、比较集合、实验条件和证据要求的限定语。
4. 识别当前段落的“论断—支撑—推论”顺序。
5. 围绕这条顺序重写整个段落，不逐个替换观察词。
6. 将结果与两类不变量、相关台账行和阅读笔记逐项比较。
7. 恢复一行一句，然后运行 `bash execs/run.sh` 构建并检查 `bash execs/scpts/lint.sh`。

如果自然表达要求做以下任一事情，应保留原文并报告问题：

- 使用尚未导入或建立指纹的证据；
- 增强或改变台账论断；
- 加入被引工作阅读笔记中不存在的事实；
- 新增规范术语或改变技术区别；
- 删除把结论限制在评估条件内所必需的限定语。

这些属于研究记录决策，不属于文字润色。

## 7. 区分三个工作流角色

同一份指南服务于三种不同职责：

- `stage-sect-drafter` 根据小节 brief、映射论断和证据形成第一版“论断—支撑—推论”结构。
  它同时更新正文和配套记录，不能用听起来合理的文字填补缺口。
- `stage-copy-editor` 是唯一以自然度为目的改写正文的角色。
  它冻结受保护内容，按段落编辑，检查小节预算，完成构建，并记录所有不能安全修改的问题。
- `stage-peer-reviewer` 只读。
  它的清晰度视角跨全文比较小节开头、贡献陈述、相关工作总结、结果解释和结论，并把公式化或宣传式段落锚定为审阅意见。

确定性 lint 的能力比上述判断流程更窄。
它扫描小节正文和表格 caption，忽略 LaTeX 注释与结构命令；高置信度聊天残留可以单独警告，普通模式必须聚集出现，并且纯文风问题不会阻断投稿。
因此 lint 干净只表示“没有触发已配置模式”，不表示“文字已经自然”。

## 8. 完成标准

一段文字只有同时满足以下条件才算完成：

- **可追溯性：** 每个外部数字和被引论断仍然连接到所需的 STAGE 记录；
- **论断守恒：** 没有陈述变得更宽、更强、更偏因果或改变归属；
- **局部职责：** 段落完成小节 brief 和所分配论断规定的任务；
- **技术稳定性：** 符号和术语符合规范；
- **表达经济性：** 每句话都推进论断、支撑、推论、局限或必要导航；
- **作者一致性：** 在 `notes/style.md` 存在时，可观察偏好与其一致；
- **审稿抵抗力：** 重要性、新颖性和结论都保持在严格审稿人能够核查的强度。

本指南刻意不提供数值化“人类评分”。
单凭文字特征不能确定是否由 AI 生成，规避 AI 检测也不是 STAGE 的目标。
