# Poster Layout

> 本文件是 `poster-layout.md` 的中文对照版，随英文版同步维护，供人阅读；运行时装载的仍是英文版。两版冲突时，以 `poster-layout.md` 为准。

`stage-pstr-builder` 如何把一个已确认的纸张尺寸和一份已批准的取舍，变成一个能编译出正确尺寸单页的源文件。在 `plan`、`render`、`check` 之前装载。`SKILL.md` 写规则，本文件写流程和数字。

一句话概括形状：**尺寸是会议事实，版式是定一次并记进计划的选择，字号是算术。**

## 1. 纸张尺寸

尺寸来自 `cycls/<cycle>/venue.yml` 且其 `confirmed:` 已设（规约 §9c）。这张表的用途是核对一个已确认的值是否合理、以及换算单位——绝不用来提供一个用户尚未确认的尺寸。

| 名称 | 竖版（宽 × 高） | 横版（宽 × 高） |
|---|---|---|
| A0 | 841 × 1189 mm | 1189 × 841 mm |
| A1 | 594 × 841 mm | 841 × 594 mm |
| 美制大幅 | 36 × 48 in（914 × 1219 mm） | 48 × 36 in（1219 × 914 mm） |
| 美制展板 | — | 4 × 8 ft 展板（1219 × 2438 mm）——这是*展板*，不是纸 |

两个坑。会议给出的是**展板**尺寸时，它说的是家具而不是纸：纸要带余量装进展板里，而纸张尺寸仍然要由用户确认。会议给出的是上限时（"海报不得超过 A0"），它给的是一个界，不是一个尺寸——记下用户选择付印的尺寸，并把这个界记在旁边。

## 2. 两种版式

在 `plan` 时选定，作为 `layout:` 记进 `POSTER_PLAN.md`；之后的 `render` 不经过 `plan` 不得更改。

### `billboard`（默认）

核心结论占据纸面中央，其余一切都是配角。海报设计文献收敛到这个版式，是因为它贴合展厅真实的阅读方式——有人隔着走道决定要不要走过来。

```
┌───────────────────────────────────────────────┐
│ T  标题 · 作者 · 单位                          │  约 10% 高
├───────────┬───────────────────────┬───────────┤
│ L         │ K                     │ R         │
│ 问题      │ 核心结论               │ 结果      │  约 65% 高
│ 方法      │ 一句话，纸面上最大的字  │ 证据      │
│           │                       │           │
│  约 22%   │  约 46% 宽             │  约 22%   │
├───────────┴───────────────────────┴───────────┤
│ F  二维码 · 联系方式 · bibkey                  │  约 10% 高
└───────────────────────────────────────────────┘
```

分区 K 承载核心结论那句话，外加至多一张配图——通常是 teaser。侧栏承载没能进入中央的主张，一条一块，图在上、说明在下。L 与 R 里的任何东西都不得成为读懂 K 的前提。

### `imrad`（传统）

三栏，从左往右读，给期待论文自身结构的会议与学科使用。会议指南要求时才用它，不要凭偏好选。

```
┌───────────────────────────────────────────────┐
│ T  标题 · 作者 · 单位                          │
├───────────────┬───────────────┬───────────────┤
│ C1            │ C2            │ C3            │
│ 动机          │ 方法          │ 结果          │
│ 贡献          │ 设置          │ 结论          │
├───────────────┴───────────────┴───────────────┤
│ F  二维码 · 联系方式 · bibkey                  │
└───────────────────────────────────────────────┘
```

核心结论在这个版式里依然存在：它是 C1 的第一块，按标题字号排。一张海报如果要读到第三栏才知道结果，那无论会议怎么要求，版面都是排错了。

## 3. 字号下限

**这些数字的出处。** 它们是海报设计文献取得共识的设计惯例，不是在本仓库里测出来的数；写在这里是为了让闸有个可核对的东西，而不是一个印象。会议自己公布的最小字号优先级高于本表；把会议的数字记进 `POSTER_PLAN.md`，并改为对着它们核对。

| 元素 | 下限（有效 pt） | 可读距离 |
|---|---|---|
| 核心结论 / 标题 | 72 | 约 4 m |
| 作者、单位 | 36 | 约 3 m |
| 块标题 | 36 | 约 2 m |
| 正文、图说明 | 24 | 约 1.5 m |
| 纸面上最小的文字（联系方式、bibkey、图内坐标轴标签） | 20 | 约 1 m |

**有效字号是算术，不是观感。** 海报文档类按它声明的纸张定一个基准字号；任何按一个尺寸写、却按另一个尺寸印的东西，都按比例缩放：

```
有效 pt = 撰写时 pt × (印刷宽度 / 撰写宽度)
```

所以在 A0（宽 841 mm）上写的 25pt 正文，印成 36 英寸（914 mm）时有效字号是 25 × 914/841 ≈ 27pt，达标；同一份文件印在 A1（594 mm）上则是 25 × 594/841 ≈ 18pt，不达标。要算，不要看。

有两处字号脱离文档类的基准字号，必须单独核对：被引入的图 PDF **内部**的文字，它随图被放置的框缩放而不随文档字号；以及任何用显式 `\fontsize` 排的东西。`check` 闸会点名纸面上最小的文字连同其算出的字号；一张图若其内部标签在被放置的宽度下低于 20pt，那是给 `/stage-figs-designer` 的发现——绝不在这里重画（`SKILL.md` 原则 4）。

## 4. 自带模板

会议给了尺寸但没给模板包时使用。文档类用 `tikzposter`：它是独立文档类，它的块模型与计划的分区表一一对应，一个分区一个 `\block` 让生成过程机械到可以审计。

```latex
\documentclass[a0paper, portrait, 25pt]{tikzposter}
\usepackage{graphicx}
% \usepackage{qrcode}   % 仅在用户给了二维码目标时

\title{...}                    % 论文标题，逐字取自 manus/main.tex
\author{...}                   % 由用户提供；不继承 ANON
\institute{...}

\begin{document}
\maketitle                                        % 分区 T

\begin{columns}
  \column{0.22}
    \block{...}{...}                              % 分区 L
  \column{0.46}
    \block{\Huge ...}{...}                        % 分区 K —— 核心结论
  \column{0.22}
    % src: mates/<slug>/<file>#<anchor>
    \block{...}{...}                              % 分区 R
\end{columns}
\end{document}
```

无论用哪个文档类都成立的规则：

1. **一个分区一个块，顺序照计划。** 有块无行、或有行无块，就是不带参数的审计要报出的漂移。
2. **`% src:` 写在它所来源的那个数字的上一行**，一个数字一条——与 `/stage-tabs-builder` 对表格行的做法相同，好让 `/stage-clms-auditor` 能像走表格那样走这张海报。
3. **图按相对路径从 `manus/figs/` 引入**，不作修改。只用 `width` 参数缩放；绝不 `trim`、`clip` 或改配色。
4. **这里根本不定义 `\todo` 宏。** 手稿的第三种状态在海报上不存在（`SKILL.md` 原则 3），而一个宏未定义的文档类会在编译期大声失败，而不是把一个标记印到墙上。
5. **各栏宽度之和要小于 1。** `tikzposter` 会加栏间距；和恰好为 1 的宽度会溢出纸张，而"装得下"那条检查要等到白渲染一次之后才抓得到。

## 5. 会议给了模板包时

整包拷进 `cycls/<cycle>/poster/template/`，逐字节照抄、不作编辑，并在 `venue.yml` 里记下 `poster_template:` 点名包内的文档类。此时不再使用 §4 的自带骨架：用的是模板包自己的文档类、自己的块或栏命令、自己的标题宏，而分区图是映射到模板包所提供的结构上，而不是映射到 `tikzposter` 上。

§3 的一切仍然适用——模板包定的是观感，不是可读性下限，而它自带的示例内容是示例，不是约束。模板包按原样编译不过时，修正写在生成出来的 `poster.tex` 里或写进汇报里，绝不写进模板包的文件：这是 `/stage-subm-packer` 原则 7 的同一条边界，理由也相同——一个为了在本地编译通过而被改过的文档类，会以印厂才发现的方式出错。

## 6. 需要跑命令的检查

- **页面尺寸与页数。** 从渲染产物上读，而不是信任文档类：`pdfinfo wkdrs/builds/poster/poster.pdf` 报出以点为单位的 `Page size`（1 in = 72 pt）与 `Pages`，后者必须恰好是 1。与已确认纸张尺寸比对到毫米。
- **灰度。** 转一份副本出来看——海报所依赖的每一处区分（数据系列、高亮、面板分组）都必须存活。工具链转不了时，如实说明，并点名改用推敲配色的方式核对了什么；绝不汇报一项没有真正跑过的检查。
- **二维码目标。** URL 或 DOI 是用户的，由其提供并记进计划的 frontmatter。不抓取任何东西来拼出它，也绝不凭记忆写一个 arXiv id——错的二维码会把一整个展厅送到别人的论文上。
